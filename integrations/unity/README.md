# Unity / Tuanjie integration (early)

Add this directory as a local package in Package Manager. In the Editor, set the RenderDocX executable under **Tools > RenderDocX**. Open a saved `.rdc`, open the workspace, or choose **Connect current Editor** to look for the current process among local RenderDoc targets. Load RenderDoc through the Editor's supported integration first; RenderDocX will not inject into the running Editor or take over a busy client. Choose **Connect Player by PID** and enter the process ID to connect an already instrumented local Player through the same non-forced handoff. Capture notification and opening are handled by the connected workspace. The Agent CLI's PID connection, busy-client refusal and reconnection have been tested against a Unity 2022.3.51f1c1 batch Editor using Direct3D 11 and RenderDoc 1.47. The new Player PID dialog, Editor menu and Editor capture workflow, and Tuanjie remain unverified.

`RenderDocX.GpuCapture.TryBegin(out var capture)` optionally wraps Unity's experimental [`ExternalGPUProfiler`](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Experimental.Rendering.ExternalGPUProfiler.html) API. Call on the main thread around appropriate rendering work and dispose the returned scope in `finally` or a `using` statement. `IsAttached` can also indicate a profiler other than RenderDoc. The scope does not load RenderDoc, ensure a frame is captured, choose a destination, or automatically open the result. Use Unity's built-in RenderDoc integration for the Editor's Game/Scene view; its operation is subject to the engine's supported graphics APIs and platforms.

The package targets the documented Unity 2020.3 API surface. Installation, compilation and handoff construction have been checked in an isolated Unity 2022.3 Editor. On Windows with Unity 2022.3.51f1c1, RenderDoc 1.47 and Direct3D 11, an isolated Development Player used `GpuCapture` to capture an offscreen camera render; RenderDocX connected to the Player, opened the resulting `.rdc`, and replayed its indexed draw. This is Player evidence for that configuration; the Editor capture workflow and Tuanjie remain unverified.

On Windows, `scripts/test-unity.ps1 -Editor <Unity.exe> -Project <disposable-project>` repeats the package installation and Editor smoke checks. `scripts/test-unity-live.ps1 -Editor <Unity.exe> -Project <disposable-project> -Agent <renderdocx-cli.exe> -Bridge <renderdocx-replay.exe>` checks a batch Editor connection, without a frame capture. `scripts/test-unity-player.ps1 -UnityCli <unity.exe> -Editor <Unity.exe> -Project <disposable-project> -Agent <renderdocx-cli.exe> -Bridge <renderdocx-replay.exe>` builds a Development Player and checks the capture and draw replay. Install this package in the disposable project before the Player test. These scripts add test assets and can change the disposable project's graphics settings; use a fresh disposable project. The Player test starts a hidden standalone process with `-load-renderdoc`; availability of that path on other Unity versions is not established. Both live tests require an installed compatible RenderDoc and Direct3D 11 device.
