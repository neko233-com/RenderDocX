# RenderDocX migration boundaries

The supplied upstream snapshot has version macros for RenderDoc 1.48 but no Git metadata. Its upstream files have been compared by Git blob ID to `v1.x` commit `5ad608809c9028da9f5c5082397cb6afe9c8dd17`; see the root README for the scope and exceptions. Capture and replay remain in the matching RenderDoc core. A separate C++ helper owns the replay lifetime and exposes a versioned process protocol to Rust, avoiding a guessed C++ ABI in Rust. The application API in `renderdoc/api/app/renderdoc_app.h` is a separate, versioned in-process capture interface.

The current workspace can launch or discover local RenderDoc targets, configure upstream capture options, launch arguments and environment modifications, connect without taking over an existing client, trigger captures and open reported local capture files. It can also show an expandable action hierarchy with optional API event rows, list and select each action's API events, navigate paged structured event parameters and buffer bytes, browse resource metadata, parent/derived links and paged static usage with event navigation, display common pipeline topology, shader/output bindings, buffers, vertex input metadata and viewports, inspect bound shader signatures and RenderDoc disassembly targets, browse GPU buffer bytes in pages, and inspect selected texture pixels, pixel history and histograms or preview and export subresources with RenderDoc's PNG mapping. Structured buffer access uses a separate replay worker and a complete structured capture export. API event names are not yet displayed with fully formatted parameters. The agent CLI shares those session implementations and additionally accepts queued captures. Common pipeline state is taken from the upstream `PipeState` implementation; OpenGL vertex input metadata is reconstructed from reflected active attributes because the upstream common implementation can contain uninitialized trailing entries. Real replay coverage exercises D3D11 and an OpenGL 3.3 capture, including selected pixel-history paths; live capture coverage includes a Unity 2022.3 D3D11 Development Player offscreen-camera capture, and a batch Editor has been connected by PID. Editor frame capture, Tuanjie, other OpenGL workflows and additional graphics APIs remain unverified. Texture export for multisample and 3D selections remains unverified; pixel and statistics coverage includes one 3D slice and a uniform D3D11 multisample fixture. `qrenderdoc` remains necessary for detailed inspection and additional workflows. There is no independent Rust `.rdc` parser or Rust implementation of the graphics replay core.

Remaining work includes:

1. Harden the version-checked replay helper, lifecycle, packaging and reproducible core builds across supported platforms.
2. Integrate target enumeration/control, launch configuration, capture progress, saved captures, remote servers, and errors using the corresponding upstream contracts.
3. Complete the event browser and port texture and mesh views, API pipeline state, resources, shader debugging, and all remaining upstream windows and workflows.
4. Integrate Unity/Tuanjie Editor and standalone workflows against the applicable documented engine APIs, graphics APIs, and versions, including capture handoff to the new frontend.
5. Extend translation resources, keyboard navigation, accessibility, settings, packaging, and platform support alongside each implemented feature.
6. Complete automated tests across protocol, UI interactions, actual captures, replay, supported GPUs, platforms, and Unity/Tuanjie before claiming parity. Compilation and mock tests alone do not establish these properties.

The agent CLI exposes RenderDoc vertex, pixel and compute shader debug trace batches, variable changes and instruction/source mappings. GPUI and the CLI can collect a trace, step through instructions or source locations, and run forward or backward to source or disassembly breakpoints. These paths have been exercised on a real D3D11 fixture, with source mapping verified for one debug-compiled compute shader. Mutable variables are now reconstructed from trace changes, but this addition has not yet received end-to-end debugger validation. The desktop collects all states before display; the vertex input viewer and mesh viewer accept instance and view indices; the bridge validates views against RenderDoc multiview broadcast count for mesh and vertex debugging. Nonzero selections still need end-to-end GPU validation. Pixel debugging accepts optional primitive and view selectors; backends may ignore selectors and GPUI selector forwarding has not yet been validated with a real capture. Source step-over and step-out are implemented but require real multi-function and cross-API validation. Source expression evaluation, other stages, indirect dispatches and additional graphics APIs are still pending or unverified.

The frame information, replay debug messages and recorded frame statistics are available in the snapshot and have initial GPUI views. The GUI polls for later debug messages and provides basic filters; the CLI supports explicit polling and paging. GPU counters can be selected, sampled and paged in GPUI and the agent CLI; broader driver and vendor-counter validation and the complete upstream counter workflow remain outstanding. Message filtering parity and formatted statistical visualizations still need migration and validation.

Pipeline color, depth and depth-resolve attachment views link to matching captured textures in GPUI. The first mip and slice are selected when valid, and the descriptor's component type is passed to PNG preview/export, picking, statistics and pixel history. A GPUI interaction test covers the handoff; a D3D11 capture test exercises the typed operations. Preview and analysis do not yet apply descriptor swizzle, and real capture UI interaction remains unverified.

The initial mesh output viewer can page vertex bytes or decode 8-, 16- and 32-bit indices with base-vertex adjustment and pipeline restart markers. GUI and CLI can also page VS/GS positions in draw-index order for regular 16- and 32-bit floats, including restart and short reads, and export those positions as CSV. A D3D11 indexed capture verifies initial draw-order rows and CSV export through the CLI. The complete attribute and geometry viewers, task/mesh draw-order decoding, other APIs, restart-enabled captures, and GPU-backed draw-order UI tests remain outstanding.

The shader inspector can switch between disassembly and captured source files, displaying source in 200-line pages. The CLI's shader report exposes complete source contents, and both GUI and CLI can export a complete source file or disassembly without replacing an existing file. GUI and CLI support session-scoped compilation, shader replacement and revert through RenderDoc. Shader editor drafts can be stored in and reopened from the upstream `EditedShaders` section; loading a draft does not apply it. Multi-file source expansion follows the upstream editor's include matching, and stored compile flags can be passed to the device. A D3D11 HLSL CLI check verifies include compilation, changed pixels, revert and compile errors. The external processor CLI passes a headless type check and subprocess fixture tests; GUI configuration and real compiler execution paths have not yet been tested. External RenderDoc interoperability, broader graphics APIs and end-to-end GUI editing validation remain outstanding.

Shader reflection reports include constant block layouts, nested variables, resources and samplers in both CLI and GPUI. The CLI can request a constant block array element using RenderDoc's dynamic binding and value decoder; GPUI can step between elements. A D3D11 compute capture verifies a read/write resource and a bound constant value; a serialization test covers nested reflected constants and a GPUI fixture tests element navigation. Other APIs, inline data and real capture GUI interaction remain outstanding.

An initial descriptor inspector pages the selected event's descriptor accesses or fixed-size stores through RenderDoc, including logical locations, resource references and sampler fields. Variable-sized store enumeration, richer typed presentation and cross-API descriptor validation remain outstanding.

Version-one capture notes and bookmarks can be read and explicitly saved through RenderDoc sections from GPUI and the agent CLI. Concurrent-writer checks are best-effort rather than an atomic lock; ordinary window-close requests are blocked for unsaved drafts and in-flight operations. Forced termination, external-editor interoperability and broader platform validation remain outstanding.

CodeGraph233 is configured for the Rust application and tests; the local index is ignored by Git. With the currently installed 0.3.1 server, C++ sources are not indexed and must still be inspected directly. Run `codegraph233 index --root . --jobs 1` to refresh the Rust graph; graph references are navigation aids and must be checked against the source.
